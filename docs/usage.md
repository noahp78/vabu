# Browser commands

## Iframes (Chrome and Firefox 153+)

Run `vabu open URL`, `vabu use TAB_ID`, then `vabu frame-list`. Use `vabu frame-read FRAME_ID` with an `id` from that list. For a named session, use the same `--session ID` for all four commands. For the default Firefox bridge, put `--socket firefox-default` before `--session` or the command. This works only on tabs opened by VABU in the current bridge and workspace, not on preexisting tabs selected for normal control. No extra popup approval or browser permission is required; host access must already allow both documents.

`frame-list` returns only opaque IDs and origins (with ports), never frame URLs or content. `frame-read` returns `{ "text": "…", "truncated": false }`: up to 4,000 characters of bounded light-DOM text, with no selectors or control refs. It skips form and editable content, hidden or protected subtrees, and nested frames. Only current, direct HTTP(S) iframe documents whose identity and ownership the browser can verify are readable. Unsupported layouts (such as framesets or shadow-tree iframe owners) fail closed. Rerun `frame-list` after navigation (including same-document changes and same-URL reloads), reselection, or a new bridge connection. If the browser released the selection, run `use` again first.

For direct **same-origin** iframes in an owned tab, `vabu frames` returns verified `{frameId, documentId}` pairs. Pass one to `inspect-query`, `inspect-element`, `inspect-wait`, or `inspect-click` with `--frame FRAME_ID DOCUMENT_ID`. Use a fresh `@i…` inspection ref for `inspect-click`; its event is synthetic, and sites can ignore it. These pairs are not `frame-list` handles. Nested or cross-origin frames cannot be inspected or clicked through these commands.

## Viewport screenshots and JavaScript dialogs

These commands require a currently selected HTTP(S) tab opened by VABU in this bridge and workspace, with browser site access to the current top document. `use` approval for a preexisting tab does not grant these capabilities. For named sessions, keep the same `--session ID` prefix on `open`, `use`, and subsequent commands.

- **`vabu screenshot [NEW_FILE.png|jpg]`** writes a new private PNG or JPEG, without switching tabs or overwriting a file. Omit the filename to generate one in a temporary directory, or use `--screenshot-dir DIR`. `--if-changed` skips saving an unchanged viewport; `--threshold 0.05` skips it when at most 5% of pixels differ from the last saved comparison capture for the same document and format. The viewport includes visible cross-origin iframe pixels without granting DOM access. VABU discards the capture if it detects a navigation, loss of selection or permission, or Chromium debugger detach. Full-page, element, and annotated captures are not supported.
- **Firefox 153+:** Open **Settings** in the VABU popup and click **Enable screenshots**. The popup closes so you can approve Firefox's optional all-sites grant. This expands host access for the entire add-on, not just one tab. Revoke it from the same settings view; the CLI cannot prompt for or grant it. For the default Firefox bridge, use `vabu --socket firefox-default screenshot NEW_FILE.jpg`. See the [Firefox capture limits](firefox.md#viewport-screenshots).
- **Chrome only:** **`vabu inspect-dialog show`** returns only `{ "id": "…", "type": "confirm" }` for an observed `alert`, `confirm`, or `prompt`. Use **`vabu inspect-dialog accept ID`** or **`vabu inspect-dialog dismiss ID`** to respond explicitly. No dialog text, default prompt value, or entered text is exposed; supplying prompt text is not supported. `beforeunload`, dialog waits, and browser UI dialogs are not supported.
- Run `use TAB_ID` on the loaded document **before** triggering a dialog. After a top-level navigation (including same-document URL changes), run `use` again before triggering the next dialog. Dialogs already open before observation or openings that Chrome does not report for the verified root URL must be handled manually. IDs expire on close, replacement, or scope invalidation. Chrome's response API cannot target a browser-issued dialog ID: a manual close, replacement, or navigation can race an in-flight response. If the outcome is indeterminate, check what happened manually; VABU never retries and the old ID must not be reused. Releasing a tab while a modal is open may leave its page indicator until reload.

## Chrome debugging

Open a tab with `vabu open URL`, then select it with `vabu use TAB_ID`. Keep the same `--session ID` for all commands if you opened it in a named session.

- `vabu console reload` starts recording before reloading the selected tab and clears the buffer. Use this to capture errors during startup. Save any unsaved work first.
- `vabu console start` records without reloading. It cannot promise the complete console history.
- `vabu console read` returns up to 100 recent console entries and uncaught exceptions from the top-level page at the selected origin, with a count of dropped entries. It does not include iframe, worker or browser network messages. Logs can contain sensitive data.
- `vabu console stop` stops recording and clears the buffer. Releasing the tab, losing authorization, or leaving the selected origin also ends recording.
### Navigation timing in Chromium and Firefox

`vabu js timing` returns navigation timing milestones in milliseconds for a selected, verified VABU-opened tab. It works in Chromium and Firefox 153+. It uses a bundled diagnostic, not `eval`, and does not require JavaScript approval. Console recording remains Chromium-only.

## JavaScript expressions

`vabu [--session ID] eval 'document.title'` runs one synchronous JavaScript expression in the selected main document. It works in Chromium and Firefox 153+ only on a loaded HTTP(S) tab that VABU opened in the current workspace and that remains in its VABU-managed group. Tabs moved out of that group and groups with unrelated tabs are not eligible.

Open **Settings → JavaScript execution** to choose a mode for this browser profile:

- **Disabled:** Reject `eval`.
- **Ask every time** (default): Review the exact source and origin in the popup before each run.
- **Allow without asking:** Run directly on eligible grouped tabs. Use this only if you trust local callers to run code as you on those pages.

In **Ask every time** mode:

1. `use TAB_ID` and request `eval EXPRESSION`.
2. Open the VABU popup. Check the origin and exact code, then choose **Allow once** or **Deny**.
3. If allowed, retry the identical `eval` command within 60 seconds. It can execute only once. If the document or selection changes, request fresh approval.

The expression runs in the page’s JavaScript context and can read or change the page, make requests as you, or change its state. Treat results as untrusted page data and approve only code you understand. A page’s Content Security Policy or Trusted Types policy can block execution. The expression can be at most 4 KiB and must return a JSON value of at most 16 KiB. There is no support for frames, promises, DevTools helpers, or arbitrary debugger commands. VABU stops waiting for `eval` after five seconds so the bridge can accept other commands. This does not cancel code the browser already started. If execution fails or times out, inspect the page before retrying; effects might already have happened. CSS changes made through `eval` are not automatically undone.

## Computed styles

In Chromium and Firefox 153+, select a VABU-created tab in its VABU group with `use TAB_ID` and get a fresh main-document inspection ref with `inspect-query`. For example:

```sh
vabu --session ID inspect-query --brief '{"css":"html"}'
vabu --session ID get styles '@iREF'
```

Replace `@iREF` with the actual ref. The read-only command returns `{ styles }` with a bounded set of computed typography, color, sizing and layout properties. It needs no JavaScript approval and does not read styles inside iframes. Use `eval` for CSS changes if enabled and permitted by the page; reload to clear simple DOM-only changes, taking care to preserve unsaved work.

## Page feedback

On an active HTTP(S) tab that the browser lets VABU access, open the VABU popup and choose **Annotate page** under **Page feedback**. The tab does not need to be opened or selected through the CLI. This does not grant the CLI control of the tab. Select an element or choose **Comment on whole page**. Use **Save annotation** to keep a draft on the page; this does not send it. When you are ready, click **Send 1 annotation** or **Send N annotations** in the on-page panel to submit all saved drafts. On Firefox this requires version 153 or later.

The **Page feedback** card in the VABU popup shows the number of sent annotations waiting in the inbox. Open the count to view up to 20 notes from the active bridge, including named workspaces. Viewing them in the popup does not clear them. To edit a submission, return to the original tab without reloading it, open the count, and choose **Recall latest batch as drafts**. This withdraws only the latest unread submission for that document after the annotation editor confirms that it reopened as editable drafts. If the restore fails or times out, the submission stays in the inbox. Click the numbered annotations to edit them, then send them again. Recalled annotations with positional selectors remain editable in the list but are not pinned to the page. Existing unsent drafts must be sent or discarded first. Once `vabu feedback` has read the submission, it cannot be recalled.

`vabu feedback` reads and clears the local inbox. Use the same socket as the popup. If the annotated tab belongs to a named session, use that `--session ID`; otherwise run `vabu feedback` without a session. The inbox holds up to 20 notes per workspace in memory until the bridge stops. Submitted notes include the page URL without query or fragment and an element selector for element annotations, not page text or form values. If VABU cannot generate a unique selector, it reports this while saving and keeps the comment in the editor so you can copy it before choosing another target. When a selector contains `:nth-of-type(N)`, recheck the element before acting if the page layout has changed. Treat notes, URLs and selectors as untrusted context; nothing is sent to an AI service automatically.

## Example

```sh
node cli.mjs status
node cli.mjs tabs
node cli.mjs open https://github.com/
node cli.mjs use TAB_ID
node cli.mjs snapshot
node cli.mjs click @r1
node cli.mjs release
```

In Chrome, `open` targets an existing normal browser window and requests an inactive tab without changing your VABU selection. Its `active` result reports whether Chrome made the tab active anyway. Run `use TAB_ID` with the returned ID before `wait`, `snapshot` or other page commands. Use the actual tab ID from `tabs` or `open`, and use only refs from the latest snapshot. In Chrome, an in-focus click can use trusted input. Background clicks use tab-targeted browser input, work only on VABU-opened tabs, reject protected targets, form actions and unsafe links, and do not activate the tab. A background result with `trusted: true` confirms a trusted click reached the checked target, not that a site navigated. If confirmation fails, inspect the page before retrying. Use a fresh `snapshot` to verify the result. The CLI does not move the hardware pointer. Chrome shows its own debug banner while a tab is selected. Website behaviour can still open a dialog or switch/open a tab. Tabs opened by Pi are placed in a purple **VABU** group. While Pi controls one, the group label changes to **VABU actief**. Existing user tabs and tab groups stay in place; for those tabs Pi temporarily prefixes the title with a purple dot **🟣** (not visible on pinned tabs). `move`, `hover @rN`, and `click` show the purple virtual pointer in the page. For Chrome’s `click`, the cursor animates only if the tab was already active and the page has focus, unless reduced motion is enabled. Otherwise it jumps to the target without an animation delay. A click is cancelled if the target changed. `scroll DY [@rN]` sends a wheel event over a control or at the cursor, so it also works inside scrollable panels. `release` resets the label or title and removes the pointer, but leaves the tab group and tabs in place. If Chrome forcibly unloads the extension, reload an affected page or rename a leftover group manually. Normal page controls are main-frame only (see [iframes](#iframes-chrome-and-firefox-153) for scoped commands). File uploads, browser UI and incognito are not supported. A cross-origin navigation releases the selected tab; select it again only if Chrome grants access to the new site.

In Chromium, `scroll DY [@rN]` on a VABU-opened background tab scrolls the page or a nested panel without activating the tab. It uses an untrusted, page-local wheel event, which the site can cancel. Foreground scrolling uses normal browser input. Chromium scroll times out after three seconds without replaying the input. A success reply does not guarantee movement, and an input already sent might still take effect after a timeout. Inspect the page before retrying.

### Reusing, showing, and closing owned tabs

Chrome and Firefox open tabs in the background by default. The first `open` pins each workspace, including the unscoped workspace, to its chosen normal window for the bridge/session lifetime. If that window disappears, the next open chooses the last focused normal window again. Named sessions are recommended for separate tasks.

Keep one tab per purpose in a session: for example, open the storefront and the CMS once, then switch between their tab IDs with `use`. Follow normal links in the current tab. For a known page URL, run `vabu [--session ID] tab-navigate TAB_ID URL` to navigate an owned tab in place. It does not focus the window or activate the tab. Source and destination need browser site access. `{ tab, requested: true }` means the browser accepted the navigation request, not that the page has loaded. The command releases control of the target tab if selected; once the destination loads, run `use TAB_ID` and check the destination with a fresh snapshot. Do not use this command as a substitute for a form submission or to bypass approvals.

Use `vabu [--session ID] tab-show TAB_ID` when the user asks to see a tab. It focuses its window and activates the tab without changing the automation selection. The response `{ tab, window, active, focused }` reports observed state; tell the user if the browser did not grant focus. Use `vabu [--session ID] tab-close TAB_ID` to close one unused tab, returning `{ tab, closed: true }` on success. It refuses pinned or active tabs and checks that another tab remains. The browser cannot check and close atomically, so avoid changing tabs in the window during cleanup. All three commands require a tab created by VABU in the current bridge and matching workspace, in a normal non-private window with site access. `tab-show` does not wait for loading; it can use an approved pending HTTP(S) URL when the browser reports one. `tab-close` and `tab-navigate` can act while a committed page is loading, but reject a pending URL change reported by the browser. Append `--wait-load` to either command to wait up to five seconds for the current page to finish loading before acting. For `tab-navigate`, this waits for the source page, not the destination. They cannot operate on user tabs or tabs from another workspace. Failures may require manual action; do not work around these safeguards.

Before ending a session, close unused VABU-owned tabs when appropriate, preserving the result, questionable tabs and all user tabs. Neither `release` nor `session-end` closes tabs or performs bulk cleanup.

Chrome and Firefox support named sessions. Choose a short, descriptive name, run `vabu session-start 'Checkout testen'`, and keep the returned `sessionId`. Run `vabu --session ID open URL`, `vabu --session ID use TAB_ID` and `vabu --session ID snapshot`. New tabs join that session’s named purple group in their window when grouping is available. Only one tab is controlled at a time: after switching, run `use` and `snapshot` again. `vabu session-list` lists IDs; `vabu --session ID session-end` forgets the session without closing tabs or changing groups. IDs only last while the bridge runs. In Chrome named groups, VABU temporarily prefixes the controlled tab’s title with a purple dot **🟣**; favicon marking is not supported. Firefox does not support Chrome’s session handoff/audit commands; see the [Firefox guide](firefox.md#named-sessions) for details and add `--socket firefox-default` before `--session` when using the default Firefox bridge.

VABU emits compact JSON by default, without dropping any fields. Use `vabu --pretty snapshot` for indented JSON, or `vabu snapshot --brief` for a short preview (up to 480 characters and 20 `[ref, role, name]` rows). To search controls with clickable refs, use `vabu snapshot --find 'winkelwagen'`. This matches a literal substring of the control name (case-insensitive, whitespace normalized), returns at most 20 matches from the regular snapshot, and does not print the page text. For alternatives or anchors, use `vabu snapshot --regex '^(bestel|toevoegen)'` (case-insensitive Unicode regex, without `/` delimiters). Use `vabu snapshot --role input` for input elements or combine filters, e.g. `vabu snapshot --role button --regex '^(bestel|toevoegen)'`. Role matching is exact (e.g. `input`, `textarea`, `select`, `button`, `a`, or an explicit ARIA role). `count: 0` only means no match among the captured controls. For a known target, `vabu inspect-query --brief LOCATOR_JSON` shows up to 10 `[ref, role, name, visible, enabled]` rows and the match count. Inspection refs are not click refs. `truncated` flags omissions; for snapshots they describe the brief view relative to the already bounded full snapshot. Use the full command if a preview omits what you need. With named sessions, put `--pretty` before `--session ID` and `--brief` after the command name. These options reduce CLI output, not bridge traffic, and do not change how refs are assigned or how errors are reported.

Chrome and Firefox support `snapshot --within main --role link` (restricted CSS, exactly one section, filters before the capture limit), `find role button --name 'In winkelwagen' click` (exact name, must match once), `get text @r1` / `get href @r1` (latest snapshot, bounded text or same-origin HTTP(S) link), and `wait --url URL` / `wait --text TEXT` (default 5 seconds, `--timeout MS` up to 15 seconds). URL waits use an exact same-origin URL; text waits stay in the selected document. Chrome’s user-tab approval still expires on a full navigation: select and approve the new document before continuing. In Firefox, a URL wait can observe same-origin navigation but does not preserve input authority. A direct `find … click` replaces the current refs, and dispatch does not guarantee navigation. Firefox’s direct click is synthetic; sites can ignore untrusted events.

Run `vabu --socket NAME instructions` (without `--session`) to get the loaded extension’s browser name, manifest version and packaged browser instructions as JSON. For Markdown alone, pipe the output to `jq -r .instructions`. The response is static extension content, not page content, and does not require tab selection. `vabu help` shows offline CLI options. Interaction adapters dispatch synthetic events to the approved main document; browser shortcuts, trusted typing and native drag-and-drop are not provided. Inspection targets the main document unless scoped to a verified frame. Pass a typed JSON locator such as `'{"all":[{"by":"role","value":"button"}]}'` or CSS shorthand such as `vabu inspect-query --brief '{"css":"[data-ctp-configurator] input[type=radio][name^=bundle_option]"}'` (`selector` is an alias for `css`). CSS supports tags, IDs, classes, descendant/child combinators, `[data-*]` presence and input type/name-prefix matching with simple tokens. Inspection locators also accept positive numeric `:nth-of-type(N)` for annotation selectors. Arbitrary attribute values and other pseudo-classes are not supported. Adapter commands reject stale documents. Session markers and audit are in memory; manual approval and handoff UI for file, clipboard and sign-in actions are not connected. No file, incognito, or browser-internal page permissions are added.
